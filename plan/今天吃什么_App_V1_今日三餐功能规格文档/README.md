# 「今天吃什么」App V1 —— 今日三餐功能规格

> 版本：V1.0  
> 平台：Android  
> 技术：Kotlin + Jetpack Compose  
> 相关组件：`TodayMealsSection` / `MealSection` / `MealRecipeCard` / `MealEmptyState`

---

## 1. 功能定位

“今日三餐”用于在首页集中展示和管理当天的：

- 早餐
- 午餐
- 晚餐

用户可以直接看到本餐安排的菜品、菜品图片及简单信息，并进行：

- 修改菜品
- 完成用餐
- 无安排时进行推荐/安排

核心目标：

> **让用户不进入详情页，也能快速看清这一天三餐吃什么，并在当前餐次快速完成操作。**

---

## 2. 三餐标题与图标

三餐标题统一采用：

`图标 + 餐次名称 + 时间（可选）`

### 早餐

使用：

```text
Icons.Outlined.WbSunny
```

建议：
- 24dp；
- 与标题垂直居中；
- Primary Purple；
- 标题：“早餐”。

### 午餐

建议使用“太阳正午/高位太阳”风格图标，视觉上与早餐形成同一套线性图标体系。推荐使用 Material Symbols 的 `wb_sunny`/太阳高亮状态的变体，或项目自定义的正午太阳 Icon。

关键要求：
- 不使用餐具 emoji 代替；
- 风格与早餐、晚餐保持一致；
- 线性、轻量、紫色。

### 晚餐

建议使用“月亮/夜间”图标，最接近截图的表达是：

```text
Icons.Outlined.Nightlight
```

也可以使用项目图标库中的 Moon / Nightlight 线性图标。

关键要求：
- 24dp；
- Primary Purple；
- 与早餐、午餐图标保持同一视觉重量。

> 说明：截图中的午餐/晚餐图形属于“太阳/时间段”和“月亮/夜间”语义图标；实现时建议统一使用 Material Icons/Material Symbols，而不是直接用系统 Emoji，这样才能保持 Android UI 的线性风格一致性。

---

## 3. 三餐信息结构

推荐统一为：

```text
[MealIcon] [MealTitle] [MealTime]

[菜品区域]

[修改菜品] [完成用餐]
```

早餐、午餐、晚餐保持相同数据结构，但允许根据“当前餐次”产生视觉强化。

---

## 4. 已安排状态

当某个餐次存在菜谱时，显示菜品卡片。

### 菜品布局规则

> **一行展示两个菜品。**

例如午餐：

```text
┌───────────────┐  ┌───────────────┐
│               │  │               │
│   菜品图片     │  │   菜品图片     │
│               │  │               │
├───────────────┤  ├───────────────┤
│ 麻辣烫         │  │ 外婆菜炒蛋      │
│ 微辣 · 15分钟  │  │ 家常 · 20分钟   │
└───────────────┘  └───────────────┘
```

要求：

- 每行最多 2 个菜品；
- 图片必须足够大；
- 菜品名称清晰；
- 辅助信息弱化；
- 同一餐超过 2 道时换行；
- 不建议在首页把图片做成很小的圆形缩略图。

---

## 5. 菜品图片要求

每个菜品卡片中：

```text
图片 > 菜名 > 辅助信息 > 操作
```

建议比例：

- 卡片宽度约 48%；
- 图片高度 100～120dp；
- 圆角 14～16dp；
- 使用 `ContentScale.Crop`；
- 菜品主体应该清晰可识别。

原则：

> 宁愿减少同屏信息，也不要把菜品图片缩小到无法识别。

---

## 6. 菜品数量策略


## 7. 底部操作区

每个已安排的餐次底部统一有两个主要操作：

```text
[ 修改菜品 ]    [ 完成用餐 ]
```

但是：

> **两个按钮禁止使用完全相同的视觉样式。**

---

## 8. “修改菜品”按钮

定位：

> Secondary Action / 次级操作

建议：

- 浅紫色背景；
- 文字 Primary Purple；
- 无强阴影；
- 不使用强渐变；
- 圆角 16～18dp；
- 高度 48dp。

示例：

```text
┌────────────────┐
│    修改菜品     │
└────────────────┘
```

建议色：

```text
背景：#EEE9FF
文字：#8068E8
```

---

## 9. “完成用餐”按钮

定位：

> Primary Action / 主操作

因为“完成用餐”会触发库存扣减，所以应该具有更高操作优先级。

建议：

- 紫色渐变/实色；
- 白色文字；
- 圆角 16～18dp；
- 高度 48dp；
- 可以使用轻微阴影。

推荐：

```text
#8068E8 → #9B86EE
```

示例：

```text
┌────────────────┐
│   ✓ 完成用餐    │
└────────────────┘
```

---

## 10. 为什么两个按钮必须区分

如果两个按钮完全一样，用户会难以理解操作优先级。

建议：

```text
修改菜品 = Secondary
完成用餐 = Primary
```

视觉权重：

```text
完成用餐 > 修改菜品
```

---

## 11. 完成用餐交互

用户点击：

```text
完成用餐
```

打开确认层/BottomSheet：

```text
完成用餐

本次预计消耗：

番茄      -2 个
鸡蛋      -3 个
食用油    -10 ml

[修改用量]

      [取消]   [确认完成]
```

确认后：

```text
更新库存
+
写入库存流水
+
记录 MealRecord
+
更新 MealPlan 状态
```

## 12. 无安排状态

没有安排某一餐时，不建议显示普通白色空卡片。

采用专用 Empty State：

```text
┌─────────────────────────────┐
│                             │
│          厨师帽插画          │
│                             │
│       还没有安排晚餐哦~      │
│   根据你的食材和口味，帮你推荐 │
│                             │
│         [✨ 帮我推荐]        │
│                             │
└─────────────────────────────┘
```

```text

```

- 波浪；
- 柔光；
- 叶片；

## 14. “帮我推荐”按钮

这个按钮需要比原截图中的按钮更加醒目。

定位：

> Primary CTA

建议：

```text
高度：44～48dp
圆角：22～24dp
背景：#8068E8 → #9B86EE
文字：白色
```

内容：

```text
✨ 帮我推荐
```

按钮宽度建议：

```text
140～170dp
```

居中或位于 Empty State 下方居中区域。

---

## 15. “帮我推荐”的行为

点击后：

```text
当前餐次
   ↓
获取今日推荐
   ↓
结合当前库存/临期状态
   ↓
计算推荐
   ↓
打开推荐选择层
```

用户选中菜谱：

```text
→ 添加到当前餐次
```

---

## 16. 当前餐次视觉强化

首页根据当前时间确定：

```text
早餐
午餐
晚餐
```

当前餐次增加轻微视觉强化：

- 标题颜色更明确；
- 卡片边框/背景略加强；
- “完成用餐”按钮保持 Primary；
- 其他餐次弱化。

但不要让三个餐次产生完全不同的设计语言。

## 22. 推荐 Compose 控件

菜品网格：

```kotlin
LazyVerticalGrid(
    columns = GridCells.Fixed(2)
)
```

但由于首页本身通常是 `LazyColumn`，更建议根据实际滚动结构考虑：

```kotlin
LazyColumn
    └── item {
        Row {
            MealRecipeCard()
            MealRecipeCard()
        }
    }
```

这样更容易控制首页的整体纵向滚动。

每个餐次至少包含：

```text

```

### EMPTY

显示：

```text
还没有安排
[帮我推荐]
```

### PLANNED

显示：

```text
菜品
[修改菜品] [完成用餐]
```

### COMPLETED

建议弱化：

```text
✓ 已完成
```

不再显示可重复点击的“完成用餐”。

---

## 26. 已完成餐次

完成后：

```text
晚餐 ✓ 已完成
```

菜品保留历史展示。

底部操作可以改为：

```text
查看记录
```

或者只显示：

```text
已完成
```

V1 推荐保持简单。

---

## 27. 数据与库存联动

“完成用餐”是业务闭环入口：

```text
MealPlan
   ↓
CompleteMealUseCase
   ↓
计算 RecipeIngredient
   ↓
用户确认实际消耗
   ↓
InventoryItem 更新
   ↓
InventoryTransaction
   ↓
MealRecord
```

数据库操作必须尽量处于同一事务中。

# 30. 最终产品定义

> **今日三餐模块用于以早餐、午餐、晚餐三个固定餐次展示用户当天的饮食安排。每个餐次采用“图标 + 餐次 + 时间 + 菜品网格 + 操作区”的统一结构；有菜谱时，菜品以两列网格展示，确保图片具有足够视觉尺寸，并在底部提供区分明显的“修改菜品”和“完成用餐”两个操作，其中“完成用餐”为 Primary CTA；没有安排时进入 Empty State，以低饱和紫渐变背景承载轻量厨师帽插画，并通过醒目的“帮我推荐”按钮引导用户生成当前餐次推荐。**

---

# 31. 一句话设计原则

> **让用户一眼看清三餐吃什么，看到菜品就能识别，想修改就修改，想完成就完成；没有安排时，不让用户面对空白，而是主动给出“帮我推荐”的下一步。**
