# 01｜产品需求文档 PRD

## 1. 产品定义

**产品名称：** 今天吃什么  
**平台：** Android  
**开发语言：** Kotlin  
**V1 定位：** 个人优先、本地优先的日常饮食管理工具。

### 1.1 产品定位

围绕用户每天最真实的饮食决策建立闭环：

> 我有什么 → 我能做什么 → 今天吃什么 → 吃完剩什么 → 什么快过期 → 下一顿吃什么

### 1.2 用户价值

| 用户问题 | 产品解决方式 |
|---|---|
| 每天不知道吃什么 | 三餐计划、随机推荐、库存匹配推荐 |
| 收藏的菜谱太乱 | 个人菜谱库、分类、标签、收藏、搜索 |
| 食材放冰箱后忘记用 | 库存记录、保质期、临期提醒 |
| 吃完不知道库存变多少 | 完成用餐时半自动扣减 |
| 临期食材容易浪费 | 临期优先推荐 |

## 2. 目标用户

### 2.1 核心用户

- 独居/单身用户
- 情侣/夫妻
- 小型家庭
- 喜欢自己做饭的人

### 2.2 V1 用户模型

V1 默认以**一个手机、一个本地用户空间**为主，不强制注册账号。

家庭共享、云同步、跨设备同步统一后移。

## 3. 产品目标

### 3.1 核心目标

用户打开 App 后，能够在短时间内完成以下任一行为：

- 确定今天某一顿吃什么
- 查看快过期食材
- 根据现有食材找到可做菜谱
- 吃完后快速更新库存

### 3.2 北极星指标

建议第一阶段关注：

> **月度通过 App 完成安排的餐次数量**

辅助指标：

- 每周活跃天数
- 完成用餐数量
- 库存更新次数
- 临期食材被消耗的数量
- 菜谱再次使用率

## 6. 首页需求

### 6.1 首页职责

首页不是资讯流，而是“今日饮食控制台”。

### 6.2 首页模块

1. 日期
2. 临期提醒
3. 早餐卡片
4. 午餐卡片
5. 晚餐卡片
6. 今日备注
7. 推荐入口

### 6.3 餐次卡片

每个餐次允许多个菜品。

```text
早餐
├── 番茄鸡蛋面
└── 牛奶

午餐
├── 番茄炒蛋
├── 蒜蓉生菜
└── 米饭

晚餐
└── 未安排
```

### 6.4 餐次操作

- 添加菜品
- 替换菜品
- 删除菜品
- 调整菜品顺序
- 查看菜谱
- 完成用餐

## 7. 点菜需求

### 7.1 手动选择

```text
餐次 → 添加菜品 → 搜索菜谱 → 选择 → 确认
```

### 7.2 随机推荐

从用户当前有效菜谱中随机选择，优先过滤：

- 已归档菜谱
- 最近频繁出现的菜谱

### 7.3 智能推荐 V1

推荐基于规则，不依赖 AI。

推荐因素：

- 库存匹配度
- 临期食材匹配度
- 收藏加分
- 最近未食用加分
- 最近重复扣分
- 制作时间惩罚

## 8. 菜谱需求

### 8.1 菜谱字段

- 名称
- 图片
- 简介
- 分类
- 标签
- 难度
- 制作时间
- 食材
- 调料
- 制作步骤
- 备注
- 收藏状态

### 8.2 菜谱与库存关系

```text
Recipe
  ↓
RecipeIngredient
  ↓
Ingredient
  ↓
InventoryItem
```

菜谱不直接保存库存数量；菜谱只描述“做这道菜需要什么”。

## 9. 食材/库存需求

### 9.1 食材字典与库存分离

`Ingredient` 表示“番茄”这一标准食材。  
`InventoryItem` 表示“用户手上的这一批番茄”。

这样可以支持同一种食材存在多个批次、不同保质期。

### 9.2 库存字段

- 食材
- 数量
- 单位
- 数量级别（少量/适量/充足）
- 购买日期
- 生产日期
- 过期日期
- 存放位置
- 备注

### 9.3 库存状态

UI 动态计算，不建议把临期状态永久写死到数据库：

- 已过期
- 紧急：0~1 天
- 临期：2~3 天
- 正常：超过阈值

阈值通过设置可调整。

## 10. 完成用餐

### 10.1 核心交互

```text
点击“完成用餐”
    ↓
读取本餐次菜谱
    ↓
根据 RecipeIngredient 计算预计消耗
    ↓
弹窗展示预计消耗
    ↓
用户可以修改实际消耗
    ↓
确认
    ↓
事务内完成：
  1. MealRecord
  2. InventoryItem 更新
  3. InventoryTransaction 写入
  4. MealPlan 状态变更
```

### 10.2 库存不足

库存不足**不能阻止点菜**。

例如：

> 需要鸡蛋 3 个，库存 1 个。

允许用户继续安排，但展示警告。

## 11. 临期提醒

首页展示：

> 你有 2 种食材即将过期

点击后：

- 查看临期库存
- 查看匹配菜谱
- 一键加入某餐次

## 12. “我的”需求

V1 主要负责：

- 基本用户信息
- 临期通知开关
- 提醒提前天数
- 默认餐次时间
- 默认份量
- 数据导出
- 数据恢复
- 关于

不强制账号登录。

## 13. 产品边界原则

### V1 不做的事情

- 社交
- 社区
- 在线商城
- 家庭权限管理
- 复杂营养学模型
- 多设备实时同步

原因：这些功能不会直接帮助验证“今天吃什么”核心闭环。
