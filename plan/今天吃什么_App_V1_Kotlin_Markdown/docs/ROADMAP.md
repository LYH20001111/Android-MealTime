# 07｜MVP 开发路线与验收标准

## 1. 开发顺序

不要按照“先把四个页面做完”的方式开发，而应该按核心业务闭环推进。

### Phase 1：工程与数据库

- Kotlin 项目
- Compose 基础框架
- Navigation
- Room
- 基础 Entity / DAO
- Repository

### Phase 2：菜谱

- 菜谱列表
- 搜索
- 分类/标签
- 新增
- 编辑
- 详情
- 收藏

### Phase 3：库存

- 食材字典
- 库存列表
- 新增库存
- 编辑库存
- 保质期
- 临期排序

### Phase 4：首页点菜

- 三餐
- 添加菜品
- 删除/替换
- 今日备注

### Phase 5：用餐闭环

- 完成用餐
- 预计消耗
- 实际消耗调整
- 库存扣减
- 库存流水
- MealRecord

### Phase 6：推荐

- 随机推荐
- 库存匹配
- 临期优先
- 最近重复控制

### Phase 7：通知与数据管理

- 临期本地通知
- 数据导出
- 数据恢复
- 设置

## 2. V1 验收标准

### 菜谱

- 可以新建菜谱
- 菜谱可关联多个食材
- 可以搜索菜谱
- 可以编辑和归档

### 库存

- 可以记录数量和单位
- 可以设置过期日期
- 临期按日期升序
- 库存数量可人工调整

### 点菜

- 每天支持早餐/午餐/晚餐
- 每个餐次支持多个菜
- 菜品必须来自菜谱库

### 完成用餐

- 自动读取菜谱食材
- 自动生成预计消耗
- 用户可调整
- 确认后库存减少
- 写入库存流水
- 写入 MealRecord

### 推荐

- 能根据库存计算匹配度
- 临期食材有额外权重
- 最近重复菜品降低权重

### 通知

- 用户打开提醒后，可以收到临期提醒
- 提醒规则来自设置中的提前天数

## 3. V1 必须完成的一条演示路径

```text
新增番茄炒蛋
↓
添加番茄 2 个 + 鸡蛋 3 个
↓
录入库存：番茄 4 个 + 鸡蛋 8 个
↓
首页 → 午餐 → 添加番茄炒蛋
↓
完成用餐
↓
确认番茄 -2、鸡蛋 -3
↓
库存变成番茄 2、鸡蛋 5
↓
番茄设置为明天过期
↓
首页出现临期提醒
↓
点击优先安排
↓
推荐番茄相关菜谱
```

## 4. 产品冻结点

进入正式编码前，以下内容需要冻结：

- 四大页面信息架构
- MealPlan 的餐次定义
- 库存扣减规则
- 菜谱与 Ingredient 的关系
- InventoryTransaction 的流水语义
- Design Tokens
- V1/P1/P2 功能边界
