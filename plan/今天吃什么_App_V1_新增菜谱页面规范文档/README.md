# 「今天吃什么」App V1 —— 新增菜谱页面 UI / 功能规范

> 版本：V1.0  
> 平台：Android  
> 技术栈：Kotlin + Jetpack Compose + Room  
> 页面：新增菜谱（Add Recipe）  
> 设计方向：低饱和紫渐变、轻量表单、图片驱动、分层输入

---

# 1. 页面定位

“新增菜谱”页面用于帮助用户快速建立一条自己的菜谱记录。

页面设计的核心不是“让用户把所有信息一次填完”，而是：

> **先轻松把这道菜记录下来，再慢慢补充完整。**

因此页面必须让用户明显感受到：

```text
核心信息
    ↓
菜名
封面
分类

基础菜谱信息
    ↓
难度
制作时间

菜谱主体
    ↓
食材
调料
做法

附加信息
    ↓
简介
备注
标签
```

```text

```

```text

```

---

# 3. 原页面问题

当前页面主要问题：

1. 所有字段视觉权重接近。
2. 菜名、封面、分类虽然标注 `*`，但没有形成明显的核心区域。
3. 页面较长，用户容易产生“必须填很多东西”的心理压力。
4. 食材、调料使用横向输入行，视觉上容易产生表格感。
5. 标签已经支持自定义，但删除能力不够直观。
6. 保存按钮位于页面最底部，滚动后操作成本较高。
7. 简介、备注、标签与主体信息平铺，页面显得冗长。
8. 大量白色输入框叠加，整体比较像后台表单，而不是生活方式 App。

# 49. 图片视觉规范

封面必须承担较强视觉作用。

要求：

- 图片主体清晰；
- 真实食物图片优先；
- 避免空白背景占比过高；
- 图片不得被过度压缩；
- 圆角 20dp；
- 上传后优先展示图片，而不是继续显示“上传控件”。

# 55. 与“今日推荐”的关系

新菜谱当天创建：

> 默认不立即加入当天已经生成的“今日推荐”。

第二天开始参与随机筛选。

原因：

> “今日推荐”以自然日固定，避免当天内容突然改变。

# 56. 与库存的关系

# 60. 最终设计原则

> **新增菜谱不是一张“必须填写完整”的表单，而是一个可以从最少信息快速开始、再逐步补充的菜谱编辑空间。**

最终用户体验：

```text
“我想记一道菜”
        ↓
写名字
        ↓
放一张图片
        ↓
选个分类
        ↓
保存
        ↓
完成
```

而对于希望记录完整菜谱的用户：

```text
继续添加食材
继续添加调料
继续写步骤
继续补充简介
继续添加标签
```

两种用户都应该被支持。
