# 「今天吃什么」App V1 首页 UI 优化说明

> 文档版本：V1.0  
> 适用平台：Android / Kotlin + Jetpack Compose  
> 主题视觉：低饱和紫渐变  
> 核心页面：首页  
> 目标：让首页从“用餐记录工具”升级为“帮助用户快速决定今天吃什么”的生活方式型首页。

---

# 1. 优化结论

当前首页的功能结构是正确的，但视觉表达更接近“信息管理页面”，没有充分突出菜品本身。

最核心的问题可以概括为：

> **用户打开首页后，应该第一眼看到“吃什么”，而不是第一眼看到“按钮和列表”。**

因此本次优化不是简单调整颜色、字号或圆角，而是重新建立首页的信息层级：

```text
问候 / 日期
    ↓
临期食材提醒
    ↓
今日推荐
    ↓
今日三餐
    ↓
智能推荐
    ↓
今日备注
    ↓
底部导航
```

其中最重要的三个视觉重点：

1. **菜品图片更大，让用户不需要点进去就能识别菜品。**
2. **今日推荐成为首页的核心入口。**
3. **智能推荐与临期食材建立联系，让 App 从“记录”变成“辅助决策”。**

---

# 2. 原首页主要问题

## 2.1 菜品图片过小

当前菜品主要采用：

```text
小圆形图片 + 菜品名称
```

图片尺寸大约只有 36～40dp。

问题：

- 无法快速识别菜品；
- 图片无法产生食欲；
- 菜品与普通文字列表没有区别；
- 用户必须点进详情页才能真正了解是什么菜。

### 优化要求

普通菜品图片建议：

- 宽：80～120dp；
- 高：72～100dp；
- 圆角：14～16dp；
- 使用真实菜品摄影图；
- 图片优先级高于辅助信息。

重点推荐卡片可以使用更大的横向图片，甚至让图片占据卡片右侧约 40%～50% 的空间。

---

## 2.2 三餐视觉层级完全相同

当前：

```text
早餐
午餐
晚餐
```

三块基本使用同样的卡片样式，导致：

- 不知道当前最值得关注的是哪一顿；
- 首页缺少视觉重点；
- 页面像一个普通列表。

### 优化要求

三餐仍然保留，但根据当前时间突出当前餐次。

例如晚上 18:55：

```text
早餐      次要
午餐      次要
晚餐      主视觉
```

当前餐次应该具备：

- 更明显的标题；
- 更大的菜品图片；
- 更明确的“完成用餐”按钮；
- 更强的紫色视觉权重。

---

## 2.3 首页顶部信息价值不足

当前顶部主要是：

```text
9月7日 星期一     🔔
```

信息量低。

### 优化要求

顶部改为：

```text
晚上好 👋
今天吃什么？

9月7日 · 星期一                         🔔
```

作用：

- 增强生活方式属性；
- 建立每日使用习惯；
- 直接强化产品核心问题：“今天吃什么”。

---

## 2.4 “帮我安排”太像普通按钮

当前：

```text
今天还没有安排
[帮我安排]
```

功能没问题，但视觉上不够重要。

### 优化要求

升级为“智能安排卡片”。

建议：

```text
┌─────────────────────────────┐
│ ✨ 今天吃什么                │
│ 根据你的库存和口味帮你安排    │
│                             │
│              [一键安排 →]    │
└─────────────────────────────┘
```

背景采用：

```text
浅紫 → 淡紫粉
```

或低对比度紫色渐变。

---

## 2.5 操作按钮占据太多视觉权重

当前：

```text
[修改菜品] [完成用餐]
```

两个按钮面积很大。

问题：

> 用户真正关心的是“菜是什么”，而不是按钮是什么。

### 优化要求

操作按钮降级：

```text
修改       ⋯        [完成用餐]
```

其中：

- “完成用餐”为 Primary CTA；
- “修改”为 Secondary Action；
- 更多操作进入“⋯”菜单。

---

## 2.6 智能推荐与今日备注缺少设计角色

当前“智能推荐”和“今日备注”被放在普通白色区域里，容易变成：

> 功能附属项。

但实际上它们应该成为首页的功能特色。

# 27. 首页应该避免的问题

不要：

- 使用太多按钮；
- 使用太多纯文字列表；
- 使用过多颜色；
- 使用大面积高饱和紫；
- 每个模块都做成同样大小；
- 图片缩小到无法识别；
- 把“修改 / 删除 / 管理”放在视觉中心；

# 33. 最终首页设计原则

整个首页必须遵循 5 条原则：

## 原则 1：先看到菜，再看到操作

菜品图片 > 菜名 > 辅助信息 > 操作。

---

## 原则 2：一个页面只能有一个第一重点

首页第一重点：

> 今日推荐。

---

## 原则 3：让库存真正影响推荐

不能让：

```text
食材页面
```

和：

```text
首页
```

成为两个孤立的系统。

---

## 原则 4：减少“管理感”

少出现：

```text
编辑
删除
管理
设置
```

多出现：

```text
今天吃什么
推荐
安排
完成
快过期
```

---

## 原则 5：保持低饱和紫的生活方式感

紫色是品牌视觉。

但是：

> **菜品图片才是首页的视觉主角。**

紫色负责：

- 品牌；
- 引导；
- CTA；
- 状态；
- 层级。

不要用紫色去“压住”菜品图片。

---

# 34. 这次首页优化最终目标

优化后用户从首页应该可以在 3～5 秒内完成以下认知：

```text
① 今天是几号？
② 哪些东西快过期？
③ 推荐我今天吃什么？
④ 早餐 / 午餐 / 晚餐安排了吗？
⑤ 如果没有，能不能帮我安排？
```

这五件事情就是首页存在的核心价值。

# 37. 一句话设计结论

> **把“今天吃什么”从一个记录入口，设计成一个每天打开就能获得答案的首页。**

图片负责“想吃”，推荐负责“决定”，库存负责“合理”，临期负责“及时”，备注负责“个性化”。

这样首页才真正成为整个 App 的核心。
