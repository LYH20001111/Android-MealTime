## 1. 产品定位与 V1 目标

**一句话定位**：不是简单的菜谱记录工具，而是帮助用户决定"今天吃什么"，并优先把家里的食材吃掉。

**核心闭环**：

```text
菜谱库（我会做什么） → 每日点菜（今天吃什么） → 完成用餐（吃掉什么）
→ 库存扣减 → 临期检测（什么该先吃） → 推荐菜谱（下一顿吃什么） → 回到点菜
```

**V1 目标**：

- 用户打开 App 后 **1 分钟内完成一顿饭的安排**。
- 吃完后在**最少操作**下更新库存（半自动扣减）。
- 临期食材**进入首页并参与推荐**。
- 北极星指标：月度通过 App 完成安排的餐次数量。

**V1 边界原则**：只做一个完整而稳定的闭环，不做"功能很多的生活平台"。

## 3. 技术选型与架构

### 3.1 技术栈

```text
Kotlin
├── Jetpack Compose      UI（含 Material 3）
├── Navigation           单 Activity 页面导航
├── ViewModel            页面状态
├── StateFlow            UI 状态流（UiState<T>：Loading / Success / Error）
├── Room                 本地数据库（唯一数据源）
├── Kotlin Coroutines    异步任务
├── Repository           数据访问抽象
├── UseCase              核心业务逻辑
└── WorkManager          临期检测与本地通知
```

- **本地优先**：无服务器、无账号，Room 即全部数据源；未来云同步时在 Repository 内扩展 LocalDataSource + RemoteDataSource，上层不动。
- **依赖注入**：遵循技术基线"V1 暂不引入复杂依赖"，采用 **AppContainer 手动注入**（App.kt 中构建 Repository/UseCase 并传递给 ViewModel 工厂），不引入 Hilt。
- **图片**：封面图通过 Photo Picker 选择，文件存 App 私有目录，数据库只存 `imageUri` 字符串，不把二进制塞进 Room。
- **日期处理**：Room 落库统一用 `Long`（epoch millis / yyyy-MM-dd 字符串，见 DATABASE_ER）；业务层用 `java.time.LocalDate/LocalDateTime`，因 minSdk 24 需**启用 coreLibraryDesugaring**。
- **临期状态**：由 `expireDate` 相对当前日期**动态计算**，不作为冗余字段存储。

### 3.2 分层架构

```text
UI (Compose Screen)
      ↓
ViewModel（StateFlow<UiState>）
      ↓
UseCase（业务逻辑）
      ↓
Repository（接口在 domain，实现在 data）
      ↓
Room DAO → Room Database
```


### 3.5 核心 UseCase 清单

```text
CreateRecipeUseCase    UpdateRecipeUseCase    ArchiveRecipeUseCase
AddInventoryUseCase    UpdateInventoryUseCase AdjustInventoryUseCase
CreateMealPlanUseCase  RemoveMealPlanUseCase  CompleteMealUseCase
GetExpiringInventoryUseCase                   RecommendRecipesUseCase
ExportDataUseCase      ImportDataUseCase
```

其中 `CompleteMealUseCase` 是全 App 最关键的用例，必须在**单个 Room 事务**内完成：

```text
BEGIN
  更新 InventoryItem（按实际消耗扣减）
  INSERT InventoryTransaction（流水）
  INSERT MealRecord（实际用餐记录）
  UPDATE MealPlan（状态 → COMPLETED）
COMMIT
```

任一步失败整体回滚。

## 4. 数据库设计（Room，11 张表）

| 表 | 主键 | 核心字段 | 说明 |
|---|---|---|---|
| recipe | id | name, imageUri, categoryId, difficulty, cookingTimeMin, description, note, isFavorite, isArchived, createdAt, updatedAt | 菜谱主表；删除用归档（isArchived） |
| ingredient | id | name, type, defaultUnit, category, icon, isDeleted, createdAt | 标准食材字典；软删除 |
| recipe_ingredient | id | recipeId, ingredientId, quantity, unit, ingredientType（食材/调料）, note, sortOrder | 菜谱-食材关联；食材必须引用 Ingredient，不允许自由字符串 |
| inventory_item | id | ingredientId, quantity, unit, quantityLevel, purchaseDate, productionDate, expireDate, location, note, isDeleted | 库存批次；同一食材可多批次 |
| inventory_transaction | id | inventoryItemId, ingredientId, changeQuantity, unit, type, sourceType, sourceId, note, createdAt | 库存流水；一切库存变化必写流水 |
| meal_plan | id | date, mealType, recipeId, servings, sortOrder, status, note | 计划用餐；一餐多菜 = 多条 |
| meal_record | id | date, mealType, servings, completedAt, note | 实际用餐记录 |
| category | id | name, icon, sortOrder | 菜谱分类（预置） |
| tag | id | name, sortOrder | 菜谱标签 |
| recipe_tag | recipeId+tagId | recipeId, tagId | 多对多 |
| app_setting | key | key, value | 设置 KV |

**关系**：Recipe 1—N RecipeIngredient N—1 Ingredient；Ingredient 1—N InventoryItem 1—N InventoryTransaction；Recipe 1—N MealPlan 0..1—MealRecord；Recipe N—N Tag（recipe_tag）；Category 1—N Recipe。

**关键查询**：按 date+mealType 查今日三餐（联表 Recipe）；按 expireDate 升序查临期（过滤 isDeleted）；Recipe→全部食材；Ingredient→能做的菜；按 MealPlan/MealRecord 聚合最近食用情况（供推荐）。

**核心业务规则（R01–R10）**：

| # | 规则 |
|---|---|
| R01 | 一个餐次可包含多个菜品 |
| R02 | 点菜允许库存不足，不阻塞决策（仅警告） |
| R03 | 完成用餐才触发库存扣减 |
| R04 | 扣库存必须写 InventoryTransaction |
| R05 | 扣库存支持用户修改实际消耗量 |
| R06 | 完成用餐、库存更新、流水写入在同一事务中执行 |
| R07 | 菜谱删除不影响历史 MealRecord（归档而非物理删除） |
| R08 | 临期状态由 expireDate 动态计算，不落库 |
| R09 | 同一 Ingredient 可对应多个 InventoryItem（多批次） |
| R10 | 没有食材明细的菜谱仍可点菜，但不参与库存匹配与自动扣减 |

异常约定：库存数量为 0 时自动归档库存记录但保留流水；所有手动调整库存必须写流水。

## 5. 设计系统落地（Design Tokens）

- 所有页面**禁止魔法值**，颜色/字体/间距/圆角统一在 `core/ui` 下定义（Compose：`FoodColorScheme` / `FoodTypography` / `FoodSpacing` / `FoodShape`）。
- 视觉方向：低饱和紫渐变，柔和、干净、家庭感；渐变只用于 CTA 按钮、FAB、推荐卡重点区域，不大面积铺底。

**颜色（采用 Kotlin 基线版）**：Primary `#8B7CF6`、PrimaryDark `#7164D9`、PrimaryLight `#B8AFFB`、PrimarySoft `#F0EEFF`、Background `#FAF9FD`、Surface `#FFFFFF`、TextPrimary `#2B2940`、TextSecondary `#77748A`、TextTertiary `#A09DAF`、Divider `#E9E6F0`、Success `#79BFA7`、Warning `#E6B56B`、Danger `#D9828B`；渐变 `#A79AF7 → #7C6BE8`。
（注：产品文档 12.1 节另一套值 `#7C68E8` 等，与 Kotlin 基线冲突，按第 10 节决策采用 Kotlin 基线。）

**字体**：Display 28sp/Bold、Title 22sp/SemiBold、Headline 18sp/SemiBold、Body 16sp、BodySmall 14sp、Caption 12sp。
**间距**：4 的倍数（4/8/12/16/20/24/32dp）；页面左右边距 16dp，卡片间 12dp，大分组 24dp。
**圆角**：Small 8 / Medium 12（输入框）/ Large 16（卡片）/ XL 20（大推荐卡）/ Pill 999（Chip）；BottomSheet 顶部 24dp。
**按钮**：主按钮紫渐变、白字、高 48~52dp；次按钮淡紫底或白底紫边。阴影一律从轻。
**食材状态色**：正常 → Success/中性；临期 → Warning；已过期 → Danger；**必须配文字**（如"⚠ 番茄还有 1 天过期"），不能只靠颜色。
**页面状态**：每个关键页面必须有 Loading / Empty / Content / Error 四态；首页额外支持四种业务态（全新用户 / 有菜谱无计划 / 已安排三餐 / 有临期库存）。

## 6. 开发阶段计划

### Phase 4 · 首页与点菜（第 4~5 周，约 5 天）

- [ ] 菜谱详情"加入早/午/晚餐"复用点菜流程
- [ ] 今日备注存储（app_setting 或当日 MealPlan 备注，按 R08 精神动态读取）
- [ ] HomeViewModel 组合三餐 + 临期 + 推荐入口（组合 Flow）
- [ ] 首页四种业务态全覆盖（新用户 / 有菜谱无计划 / 已安排 / 有临期）

### Phase 5 · 用餐闭环（第 5~6 周，约 5 天）★ 最关键

**目标**：打通"点菜 → 吃饭 → 扣库存 → 流水 → 记录"核心闭环。

- [ ] 完成用餐确认页（consume-confirm/{mealPlanId}）：按餐次菜品汇总预计消耗（读 RecipeIngredient、匹配库存批次），展示"番茄 -2 个、鸡蛋 -3 个"
- [ ] 支持逐项修改实际消耗（R05）；无食材明细的菜不产生扣减项（R10）
- [ ] **CompleteMealUseCase 单事务**：更新库存 → 写流水 → 写 MealRecord → 更新 MealPlan 状态（R03/R04/R06）
- [ ] 扣减后数量为 0 的批次自动归档；扣减超出库存的处理策略（扣至 0 并在流水中记录实际值）
- [ ] 完成后首页刷新临期与推荐
- [ ] 单元测试：CompleteMealUseCase 多菜品 / 多批次 / 数量不足 / 事务回滚
- [ ] 菜谱归档后历史 MealRecord 仍可见（R07）

**验收**：番茄炒蛋用掉番茄 2、鸡蛋 3 后，库存 4→2、8→5；流水两条；MealRecord 一条；重复完成同一餐被状态拦截。

### Phase 6 · 智能推荐（第 6~7 周，约 3~4 天）

**目标**：让 App 主动回答"下一顿吃什么"。

- [ ] RecommendRecipesUseCase（规则评分，不用 AI）：

  ```text
  score = inventoryMatch × 50      库存匹配率
        + expiringMatch × 40       临期食材命中
        + favoriteBonus × 10       收藏
        + notRecentlyEaten × 10    最近未吃
        - recentRepeat × 30        近期重复降权
        (+ 制作时长惩罚：工作日偏好快手菜)
  ```

- [ ] 过滤已归档、无来源菜谱；按分数降序取 Top N
- [ ] 推荐页（recommend）：得分、推荐理由（"✓ 番茄还有 1 天过期 / ✓ 鸡蛋库存充足 / ✓ 最近 7 天没吃过"）、库存匹配情况、[加入今日]
- [ ] 首页快捷操作：随机（过滤归档与近期频繁）、智能推荐入口
- [ ] 临期提醒条"优先安排" → 按临期加分排序进入推荐
- [ ] 推荐算法单元测试（构造库存/临期/历史组合断言排序）

**验收**：临期番茄使含番茄菜谱明显加分并置顶；推荐理由与数据一致。

### Phase 7 · 通知、设置与数据管理（第 7~8 周，约 4 天）

**目标**：补齐"我的"，完成 P1 收尾。

- [ ] 我的页：用户信息（本地昵称/头像，可选）、入口列表（通知设置 / 默认设置 / 数据管理 / 关于 / 历史记录）

- [ ] 默认设置：默认三餐时间、默认份量、临期阈值（存 app_setting）

- [ ] 历史用餐记录页（按日期倒序，展示已归档菜谱名称）

## 8. V1 验收标准

### 8.1 必须通过的一条演示路径

```text
新增菜谱"番茄炒蛋"（番茄 2 个、鸡蛋 3 个）
→ 录入库存：番茄 4 个、鸡蛋 8 个
→ 首页 → 午餐 → 添加"番茄炒蛋"
→ 点击"完成用餐"，显示预计消耗（番茄 -2、鸡蛋 -3），允许修改
→ 确认后库存变为番茄 2、鸡蛋 5，并产生库存流水
→ 把番茄设为明天过期 → 首页出现临期提醒
→ 点击"优先安排" → 推荐中含番茄菜谱明显加分
→ 查看历史用餐记录：菜谱归档后记录仍然可见
```

### 8.2 分模块验收（摘要）

| 模块 | 验收点 |
|---|---|
| 菜谱 | 新建；关联多食材；搜索；编辑；归档 |
| 库存 | 数量/单位；过期日期；临期升序；人工调整 |
| 点菜 | 每天三餐；每餐多菜；菜品必须来自菜谱库 |
| 完成用餐 | 自动读食材 → 预计消耗 → 可调整 → 扣库存 → 写流水 → 写 MealRecord |
| 推荐 | 库存匹配度；临期额外权重；近期重复降权 |
| 通知 | 开关生效；提醒按设置的提前天数；每天最多一次 |

### 8.3 质量标准

| 维度 | 要求 |
|---|---|
| 可用性 | 核心流程 1 分钟内完成；空状态清晰 |
| 一致性 | 颜色/字体/间距/圆角全部走 Design Token |
| 可靠性 | 完成用餐的库存变更具备事务一致性 |
| 数据安全 | 本地保存；导出/恢复可用 |
| 扩展性 | Ingredient/Recipe/Inventory/MealPlan 关系稳定，为 V2 云同步与家庭模式预留 |

### 8.4 测试策略

- **单元测试（重点）**：推荐算法、临期计算、库存扣减、CompleteMealUseCase、数量不足处理。
- **DAO 测试（重点）**：今日餐次查询、临期排序、菜谱-食材关联、库存流水。
- **UI 测试（重点）**：四大导航、新增菜谱、新增库存、点菜、完成用餐。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 当前工程基于 View 模板，需迁移到 Compose；AGP 9.4.0-alpha05 为 alpha 版本 | Phase 0 受阻 | Phase 0 首项任务先验证工具链；必要时降级到稳定 AGP + 稳定 Compose BOM |

## 10. 开发前冻结清单与待决策项

**已冻结（进入编码前确认）**：

1. 一级导航仅 首页/菜谱/食材/我的；V1 纯本地、不登录。
2. Ingredient 与 InventoryItem 分离；库存可多批次。
3. 餐次支持多菜；完成用餐才扣库存；扣库存必写流水且可手动修正。
4. 临期状态动态计算；推荐用规则算法，不引入 AI。
5. 设计 Token 采用 Kotlin 基线版数值（第 5 节）。
6. 包名沿用实际工程 `com.skyanchor.mealtime`（设计文档中 `com.example.todayeat` 不采用）；应用显示名"饭点"。
7. **构建基线（Phase 0 已验证）**：AGP 9.4.0-alpha05 + Gradle 9.6.0 + 内置 Kotlin 2.2.10（仅应用 Compose Compiler 插件 2.2.10，不单独引 KGP）；因内置编译器最高读取 Kotlin 2.3 元数据，AndroidX 依赖锁定为 2025 年稳定版（compose-bom 2025.06.00、navigation 2.9.5、lifecycle 2.9.4、room 2.8.1、work 2.10.5、coroutines 1.10.2、coil 3.3.0、icons-extended 1.7.8）；JDK 25 工具链经 `org.gradle.java.installations.paths` 注册本地安装（foojay 下载在本机网络不可用）；coreLibraryDesugaring 开启（minSdk 24 + java.time）。

**待确认决策（不阻塞 Phase 0–1，但需在 Phase 2 前定案）**：

| D1 | 两份文档 Primary 色/渐变值不一致（`#7C68E8` vs `#8B7CF6`） | 采用 Kotlin 基线 `#8B7CF6` + 渐变 `#A79AF7→#7C6BE8`，与原型图比对后如偏差再统一 |
