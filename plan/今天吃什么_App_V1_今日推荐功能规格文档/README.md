# 「今天吃什么」App V1 —— 今日推荐功能规格文档

> 版本：V1.0  
> 适用：产品 / UI 设计 / Kotlin + Jetpack Compose 开发  
> 组件名称：`TodayRecommendationSection`  
> 核心组件：`TodayRecommendationCarousel`

---

## 1. 功能定位

“今日推荐”是首页的核心内容模块。

它不是普通菜谱列表，而是：

> **每天给用户一组固定的推荐菜，帮助用户快速决定今天吃什么。**

核心目标：

```text
用户打开 App
    ↓
看到今日推荐
    ↓
快速了解推荐菜
    ↓
选择喜欢的菜
    ↓
加入早餐 / 午餐 / 晚餐
```

---

## 2. 推荐数量规则

| 有效菜谱数量 | 今日推荐数量 |
|---:|---:|
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| ≥3 | 3 |

不为了视觉完整强行补菜。

### 无菜谱

```text
还没有推荐菜谱
先添加几道喜欢的菜吧

[去添加菜谱]
```

按钮进入“菜谱”页面的新增入口。

---

## 3. 每日刷新机制

推荐结果以“自然日”为周期。

例如：

```text
9月7日
番茄炒蛋
麻辣烫
外婆菜炒蛋
```

整个 9 月 7 日保持不变。

到了 9 月 8 日，才重新随机生成。

### 不能因为以下操作重新随机

- 打开 App
- 关闭 App
- 重新打开 App
- 切换首页/菜谱/食材/我的
- Activity 重建
- App 进程重启

---

## 4. 推荐结果必须持久化

不能：

```kotlin
Random.nextInt()
```

然后每次进入首页都重新计算。

正确逻辑：

```text
检查今天是否已有推荐
        ↓
有
        ↓
直接读取数据库
```

如果没有：

```text
查询有效菜谱
        ↓
随机抽取最多 3 道
        ↓
保存到数据库
        ↓
展示
```

---

## 5. 推荐数据模型

建议：

```text
DailyRecommendation
        │
        │ 1:N
        ↓
DailyRecommendationItem
        │
        │ N:1
        ↓
Recipe
```

### DailyRecommendation

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键 |
| recommendationDate | LocalDate/String | 推荐日期 |
| createdAt | Long | 生成时间 |

### DailyRecommendationItem

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键 |
| recommendationId | Long | 推荐批次 |
| recipeId | Long | 菜谱 |
| sortOrder | Int | 展示顺序 |

---

## 6. 随机筛选规则

V1：

> 在所有有效菜谱中纯随机抽取最多 3 道。

有效菜谱：

```text
isArchived = false
```

同时排除已删除/无效菜谱。

后续版本再增加权重：

```text
V1     = Random
V1.5   = Weighted Recommendation
V2     = Intelligent Recommendation
```

## 8. 不同菜谱数量的轮播行为

### 1 道

```text
[ A ]
```

- 不自动轮播；
- 不需要分页指示器；
- 保持完整 Hero 卡片。

### 2 道

```text
A ↔ B
```

- 支持手动滑动；
- 支持自动轮播；
- `● ○`

### 3 道

```text
A → B → C → A
```

- 支持手动滑动；
- 支持自动轮播；
- `● ○ ○`

---

## 9. 自动轮播

推荐：

```text
首次进入
↓
等待 5 秒
↓
下一页
↓
等待 5 秒
↓
继续
```

只有 2～3 道菜时自动轮播。

---

## 10. 用户手动操作

当用户开始拖动：

```text
暂停自动轮播
```

滑动完成后：

```text
保持当前卡片
↓
等待约 4～5 秒
↓
恢复自动轮播
```

目的：

> 防止自动轮播抢走用户的操作权。

---

## 11. Hero Card 视觉定位

今日推荐属于首页的：

> **Hero Card / 主视觉卡片**

视觉优先级高于：

- 今日备注
- 普通三餐卡片
- 管理入口

用户进入首页应该首先理解：

> **今天推荐吃什么。**

## 12. 推荐卡片结构

```text
┌─────────────────────────────────┐
│ ✨ 今日推荐      [为你精选]      │
│                                 │
│ 番茄炒蛋                 菜品图 │
│                                 │
│ 家常 · 15分钟 · 2人             │
│                                 │
│ [ ✨ 加入今日三餐 ]              │
│                                 │
│              ● ○ ○             │
└─────────────────────────────────┘
```

核心原则：

> 左侧内容 + 右侧菜品图片背景，但视觉上必须是一体化卡片。

---

## 13. 卡片尺寸

建议：

```text
左右外边距：20～24dp
高度：220～240dp
圆角：22～24dp
```

屏幕较小的时候：

```text
最小高度：200dp
```

优先压缩辅助信息，不要缩小菜品图片到无法识别。

---

## 14. 背景颜色

推荐低饱和紫渐变：

```text
左：#8C76E8
右：#CDBDF7
```

不建议使用高饱和紫色或大面积深紫。

---

## 15. 右侧菜品图片

图片占卡片：

```text
约 45%～55%
```

要求：

- 菜品主体清晰；
- 图片具有食欲感；
- 不需要点击详情才能识别；
- 不使用生硬的左右分栏。

---

## 16. 图片与左侧过渡

不能是：

```text
┌────────────┬──────────────┐
│ 紫色内容区 │ 菜品图片区域  │
└────────────┴──────────────┘
```

应该是：

```text
紫色内容区
████████████
     ↓
  ███████
      ↓
    ████
       ↓
      菜品图
```

使用：

- Gradient Mask
- Alpha 渐变
- Soft Blur
- Purple Overlay

让图片自然融入左侧紫色背景。

---

## 17. 图片透明度

从右向左逐渐降低：

```text
右侧：100%
中部：60～70%
左侧：10～20%
```

---

## 18. 图片模糊

不要整张图都模糊。

建议：

```text
主体：清晰
边缘：轻微模糊
向左：逐渐模糊并降低透明度
```

建议视觉 Blur：

```text
15～30dp
```

最终以真机表现微调。

## 23. 今日推荐与库存

V1：

> 今日推荐主要采用每日随机抽选。

临期/库存匹配属于后续智能能力。

未来：

```text
今日推荐
+
库存匹配
+
临期优先
```

例如：

```text
番茄明天过期
     ↓
番茄炒蛋权重提高
```

---

## 24. 与智能推荐区分

### 今日推荐

> 每天固定的一组随机精选菜。

特点：

- 每日刷新；
- 一天固定；
- 最多 3 道；
- 用于探索。

### 智能推荐

> 根据库存、临期、口味和历史行为实时计算。

特点：

- 可以实时变化；
- 更强调决策；
- 后续支持“一键安排”。

因此：

```text
今日推荐 = Daily Discovery
智能推荐 = Decision Assistant
```

## 25. 推荐模块异常状态

读取失败：

```text
暂时无法获取今日推荐

[重新加载]
```

不要展示技术异常信息。

首次读取可以使用低饱和紫色 Skeleton。

## 26. 日期跨天流程

```text
App 启动 / 首页加载
        ↓
获取当前日期
        ↓
查询 DailyRecommendation
        ↓
是否存在？
 ┌──────┴──────┐
 是            否
 ↓              ↓
读取          查询有效菜谱
推荐             ↓
             随机抽取最多3道
                    ↓
                保存数据库
                    ↓
                返回首页
```

不要求系统必须在 00:00 精确执行，可以采用“首次进入新日期时懒生成”。

---

## 27. 特殊情况

### 当天从 5 道有效菜变成 2 道

当天推荐记录仍保持稳定。

如果其中一道被删除/归档：

> UI 自动隐藏无效项，不重新随机补位。

例如：

```text
原：
A B C

C 被归档

显示：
A B
```

下一天重新生成。

### 当天新增菜谱

新增菜谱不加入当天推荐。

第二天参与随机抽取。

## 28. Compose 实现建议

核心：

```kotlin
HorizontalPager
```

状态：

```kotlin
val pagerState = rememberPagerState(
    pageCount = { recommendations.size }
)
```

自动轮播可以使用：

```text
LaunchedEffect
    ↓
delay(5000)
    ↓
animateScrollToPage(...)
```

用户交互期间通过：

```kotlin
pagerState.isScrollInProgress
```

控制自动轮播暂停/恢复。

---

## 29. 推荐循环

```kotlin
nextPage = (currentPage + 1) % pageCount
```

例如：

```text
0 → 1 → 2 → 0
```

仅在：

```text
pageCount > 1
```

时启用自动循环。

## 32. 最终产品定义

> **今日推荐是一个基于自然日生成的每日菜谱推荐 Carousel。系统每天为用户从有效菜谱库中随机筛选最多 3 道菜，推荐结果生成后当天固定保存，不因 App 启动、退出或页面切换而变化；用户可以左右滑动查看推荐，也可以在未交互状态下让推荐自动循环播放。推荐数量根据有效菜谱数量动态决定，最多 3 道。推荐卡片采用左侧内容、右侧菜品图的融合式 Hero 设计，通过低饱和紫色渐变、透明度渐变与柔和模糊让图片与背景自然衔接。**

---

## 33. 一句话设计原则

> **让用户打开 App 就看到“今天可以吃什么”，并在不增加操作成本的情况下，给用户一点每天不同的选择。**
